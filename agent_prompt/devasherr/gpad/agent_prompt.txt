#### Command Category: `gpad`
- **Function and Parameter Description**:
  The base command `gpad` scans the current directory and all its subdirectories for Go source files. It identifies struct definitions and rewrites them in place to optimize memory layout by reordering the fields. By default, it operates silently, modifying files without producing any standard output.
- **Execution Context and Sample**:
  **1. Preparation**:
  The following file is created in the working directory `/test_data/project_DEFAULT_0/`:
  - `main.go`:
    ```go
    
    package main

    // UnoptimizedStruct is designed to be reordered by gpad.
    type UnoptimizedStruct struct {
        B bool    // 1 byte
        C int32   // 4 bytes
        A int64   // 8 bytes
        E float64 // 8 bytes
        D string  // 16 bytes
    }

    ```
  **2. Command**:
  `cd /test_data/project_DEFAULT_0 && gpad`
  **3. Oracle Result**:
  ```json
  {
    "exit_code": 0,
    "stdout": "",
    "fs_diff": {
        "/test_data/project_DEFAULT_0/main.go": {
            "type": "MOD",
            "content": "package main\n\ntype UnoptimizedStruct struct {\n\tD string\n\tA int64\n\tE float64\n\tC int32\n\tB bool\n}\n struct {\n    B bool    // 1 byte\n    C int32   // 4 bytes\n    A int64   // 8 bytes\n    E float64 // 8 bytes\n    D string  // 16 bytes\n}\n"
        }
    }
  }
  ```
- **Deep Sample Analysis (Implementation Logic Reference):
  - Initial State Analysis: The file system contains a single Go file `main.go` with a struct `UnoptimizedStruct` whose fields are not ordered by size.
  - Command Behavior Analysis: The `gpad` command is executed in the directory containing `main.go`. The tool parses this file, finds the `UnoptimizedStruct` definition, and determines that its fields can be reordered for better memory alignment. The fields are sorted in descending order of their data type's size (string, int64, float64, int32, bool).
  - Final State Changes (fs_diff): The `main.go` file is modified in place. The original `UnoptimizedStruct` definition is replaced by the new, optimized version where fields are ordered by size. Note the specific, unusual format of the modified content: it contains the new struct definition followed by the text of the old struct definition. This exact output format must be replicated.
