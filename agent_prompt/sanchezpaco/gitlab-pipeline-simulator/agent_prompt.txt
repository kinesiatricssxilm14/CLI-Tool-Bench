<Project_Overview>
**CLI Tool Name**: gitlab-pipeline-simulator
**Repository Name**: gitlab-pipeline-simulator
**Core Functionality Description**:
The CLI tool simulates GitLab CI pipeline execution based on a provided YAML configuration file and a set of variables. Its core purpose is to predict which jobs will run under different conditions without needing to push changes to a repository. The tool parses the CI YAML file, evaluates `rules:if` conditions against user-provided variables, and outputs a list of jobs that would be executed. It supports string equality (`==`) and regex (`=~`) comparisons in the rules. The tool also provides options to display the scripts of matching jobs or to simply output an expanded version of the YAML configuration.
</Project_Overview>

- **Function and Parameter Description**:
  This command simulates a pipeline run by taking a single argument: the path to a GitLab CI YAML file. When no CI variables are provided on the command line, it evaluates the rules in the YAML file against a default (empty) set of variables.
- **Execution Context and Sample**:

  A single YAML file named `test_simulate_no_vars_4.yml` is created in the `/test_data/` directory with the following content, defining three jobs with different rules.
  ```yaml
  path: /test_data/test_simulate_no_vars_4.yml
  content:
  
  stages:
    - build
    - test
    - deploy
  
  build-job:
    stage: build
    script:
      - echo "Building..."
    rules:
      - if: '$CI_COMMIT_BRANCH == "main"'
  
  test-job:
    stage: test
    script:
      - echo "Testing..."
    rules:
      - if: '$CI_PIPELINE_SOURCE == "push"'
  
  deploy-job:
    stage: deploy
    script:
      - echo "Deploying..."
    rules:
      - if: '$CI_COMMIT_TAG =~ /^v[0-9]+\\.[0-9]+\\.[0-9]+$/'
  ```
  **2. Command**:

  ```json
      "stdout": "\n=== Pipeline Simulation Results ===\nJobs that would run based on current conditions:\n",
      "fs_diff": {}
  }
  ```
